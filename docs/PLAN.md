# ASCII 城市动态壁纸：初版方案与 Codex 实施计划

2026年11月2日 · @明杉
概览与原则
第一版是一张"隔着水看城市天际线"的 ASCII 动态壁纸：外滩、曼哈顿、维港三个场景，由本机的 Agent、浏览器、音乐和系统状态驱动楼宇、灯光、船与天气。前端美术原型已经定稿，接下来由 Codex 工程化，顺序是先前端（用模拟事件），后采集端，最后接 Windows 壁纸层。
设计原则
• **一种语义只用一个视觉通道。**例如"Agent 进度"只用楼层表达，不同时用颜色、粒子和文字重复表达。
• **显眼度分层。**需要你行动的 > 报错 > 完成 > 进行中 > 环境氛围。越往前越显眼，但都不刺眼。
• **余光友好。**壁纸态下慢层（天色、云、楼灯）占大面积，快层（节拍、粒子）只占小面积；所有信号先平滑再进入世界。
• **字就是材料。**画面里的文字（外墙滚动、LED 屏）用同一套字格渲染，不用浮在上面的 UI 控件。
• **确定性。**世界状态 = f(种子, 规则, 事件流)。同一段事件流必须重放出同一段画面，这是回放和分叉的前提。
• **隐私默认。**只取抽象信号；具体文字（任务标题、歌名、网址）默认只在本机显示，并有一键隐私模式。
原型现状
参考实现是单文件 ascii-city.html（WebGL2 字符网格 + 程序化世界 + 信号模拟面板），在线版本：ASCII 城市 · 美术原型。它已经实现：三个场景与地标、水面倒影、云层与雾、雨、月亮太阳、塔吊施工、外墙代码滚动、船只、步道与居民、激光秀与明珠变色、烟花、悬停说明、壁纸态与互动态、三种主题、字格密度切换。1080p 下每帧合成约 2.3 ms。
它还没有：真实数据接入、中文字符、任务步骤级进度、频谱级音乐律动、多类天气、事件记录与回放、Windows 壁纸挂载。这些就是本计划要做的。
场景与构图
三个场景共用同一套四层构图，只换地标、配色、船和灯光秀；场景是数据（一个配置对象），不是三套代码。
四层构图（自上而下）
1. 天空层，约占屏高 0 到 60%：渐变天色、星、月亮太阳、云、航班、灯光秀（激光）。夜里地平线带城市光晕，颜色随场景而定。
2. 对岸天际线：远景楼群（低、雾化、密集小窗）→ 近景写字楼与待建地块 → 地标。楼底坐在堤岸上，堤岸是一排路灯。
3. 水面：镜像天空、楼宇剪影和所有发光格，带波纹抖动和噪声断裂；船在这一层。
4. 近岸步道，约占屏高底部 14%：栏杆、路灯、地砖、Agent 居民。

地标构建方式
每个地标是一个参数化构建函数 build(H) → stamp，H 是以行为单位的高度。stamp 包含一个主体掩码（哪些格子是楼体）和一组覆盖字符（尖顶、球体、斜撑、灯）。边缘字符由掩码自动推导：上方空、左侧空且右上有楼体用 /，镜像用 \，平顶用 ─，侧边用 │。这样地标随屏幕尺寸缩放而不需要手画多套字符画。
地标高度按真实比例取相对值，以场景最高地标为 1：外滩是东方明珠 0.74、金茂 0.67、环球 0.78、上海中心 1.0。
安静区
左侧约 20% 宽度只放低矮远景楼，桌面图标落在这里不打架。设置里保留"叠加桌面图标"开关用于检查构图。
渲染架构
整屏是一张字符网格，每格存字形和颜色，CPU 合成后用一次 WebGL2 绘制输出；中文改为占两格的宽字形，由动态字形图集按需生成。
字格
• 字格尺寸按 CSS 像素定义为 1:2（细 7×14、中 9×18、粗 12×24），乘以 devicePixelRatio 取整成设备像素，保证字形锐利。
• 每格的缓冲：字形索引（Uint16）、前景 RGB、背景 RGB、发光 RGB（供倒影采样）、光照 RGB、实体 id（供悬停）、solid 标记（区分天空物体与楼体）。全部是预分配的 TypedArray。
• 打包成两张 RGBA8 纹理：A =（前景 RGB，字形低 8 位），B =（背景 RGB，字形高 8 位）。用 Uint8ClampedArray 视图写入，免去手动截断。
着色器
全屏三角形，片元里 texelFetch 取格子数据和字形图集，按覆盖度在背景色和前景色之间混合，再加暗角和主题变换（夜港原色、磷光单色绿、纸墨反相成纸上墨色）。
字形图集
• 程序绘制的字形：256 个盲文点阵、框线（─│┌┐┼═║╬ 等，保证接缝对齐）、█▀▄░▒▓、窗户 ▪。
• 字体绘制的字形：ASCII 与少量符号，以及中文。
• 升级为动态图集：2048×2048 纹理，按字格大小切成槽位，用 LRU 管理，记录每个槽位最后使用的帧号，满了淘汰最久未用的。字形索引 16 位，上限 65536。DPR 或字格密度变化时整体重建。
中文双宽
• 按 Unicode East Asian Width 判断：W 和 F 类占 2 格，其余占 1 格。
• 宽字形在图集里存成左右两个相邻槽位，分别分配两个字形索引；写入网格时左格放左半、右格放右半。这样着色器完全不用改。
• 字体用更纱黑体等宽版 Sarasa Mono SC（SIL OFL 许可），它的拉丁字母正好 1 格、汉字正好 2 格。网页原型阶段可回退到 Noto Sans SC。
• 提供统一的 drawText(x, y, str, style)：按显示宽度截断并补省略号，宽字形不会被切成半个，右边界越界的宽字整个不画。
合成顺序（每帧）
1. 清空缓冲，天空渐变，星。
2. 月亮和太阳（盲文点阵），云（城市光从下方照亮）。
3. 山脊（维港），远景楼群，近景楼，待建地块，地标，摩天轮。
4. 堤岸路灯，激光秀，航班。
5. 水面：镜像采样 + 波纹 + 月光日光倒影柱。
6. 船，大桥（曼哈顿），步道、栏杆、路灯，居民。
7. 粒子（火花、烟花及其倒影、雨），盲文粒子合并。
8. 低云层与水雾，光标提灯。
9. 光照合成：点光源累加后做 x/(1+0.6x) 压缩，按 0.26 加到背景、0.35 加到前景；打包上传。
倒影
水面第 d 行采样岸上第 wy-1-floor(1.15d) 行。楼宇剪影不加抖动，按深度淡出；发光格加正弦波纹抖动，再用噪声打断成 - 和 = 短线。烟花粒子额外写一个镜像点。
性能做法
热循环里不分配对象，字形索引提前缓存成常量；云和雾的噪声每帧只更新一半行（奇偶交替），另一半复用缓存；查表噪声代替哈希噪声。
信号映射
每类来源只负责世界里的一个层：系统管气候，音乐管节律和灯光，Agent 管楼，浏览器管船，你管城市是否醒着，时间管昼夜季节。来源之间不直接互相作用，而是通过共享的场（温度、云量、风、节拍）间接发生关系。

Agent 可视化语法
楼层等于任务步骤：任务列表的总步数是目标楼层，完成的步数是建好的楼层，正在做的那一步是带脚手架的施工层。"7 层盖到第 4 层"本身就是进度条。
楼与任务
• 会话开始时认领一块待建地块，颜色是这个 Agent 的全局颜色，塔吊、外墙代码、居民、提示文字一律用它。
• 收到任务列表（Claude Code 的 TodoWrite，Codex 的计划步骤）后，目标楼层 = 总步数 × 每步楼层数（按地块高度上限自动折算，至少 1 层）。步数增加时楼会"加盖"。
• 每完成一步，施工层封顶：脚手架上移一层，新楼层的窗户从下到上依次点亮，用 0.6 秒补间。
• 没有任务列表的会话退化为"按工具调用次数缓慢增长"，上限为地块高度的一半，避免无列表的长会话盖成最高楼。
• 会话结束：封顶仪式。楼冠亮起，从水面放一束这个颜色的烟花。楼保留在天际线上，外墙代码停止滚动，转成普通窗灯。

惯性与滞回
• 判定用的信号先做 3 分钟滑动平均，进入阈值和退出阈值之间留 6 到 15 个百分点的间隔，防止在边界来回切换。
• 天气切换本身是 20 到 40 秒的渐变：云量、雨强、雾浓度都是连续参数，状态只决定它们的目标值。
• 同一天气至少维持 2 分钟，雷暴的闪电除外。
季节与节日
• 按本机日期：12 月到 2 月，曼哈顿场景的雨换成雪，外滩场景有 30% 概率换成雪，维港不下雪（盲文雪片慢落，屋顶和栏杆逐渐积白）。开了真实天气层时以实况为准。
• 节日：春节和元旦夜里在水面上放一场 3 分钟的烟花秀；其他节日先不做，留配置表。
真实天气层（可选，默认关）
• 设置里选一个城市（默认用当前场景的城市），每 30 分钟拉一次实况，例如用免费的 Open-Meteo 接口。
• 两种模式："真实覆盖"让实况决定天气，系统信号只影响强度；"叠加"让实况和数据天气取更强的一个。
• 离线或拉取失败时静默回退到数据天气。
音乐律动
音乐用系统音频回环采样做频谱分析，拆成低、中、高三个频段，各管一件事；切歌时换调色板；壁纸态下律动强度自动减半。
采样与分析（采集端）
• WASAPI loopback 采样系统输出，单声道下混，1024 点 FFT，约每 23 毫秒一帧（44.1 kHz）。
• 频段：低 20–150 Hz，中 150–2000 Hz，高 2000–12000 Hz。每段做对数能量，再用最近 10 秒的分位数自适应归一化到 0 到 1，安静的歌也能动起来。
• 起音点：频谱通量超过自适应阈值即判定；节拍：对起音点序列做自相关估计 BPM 和相位。
• 能量包络：8 秒窗口的平均能量，用来判断"副歌"段落。
• 推送频率 30 Hz，前端再做插值，壁纸态 12 帧时取最近值。

• 柱子之间按频率从低到高从左到右排；每栋楼的能量值做 120 毫秒上升、400 毫秒下降的包络，看起来像真实的电平表。
克制
• 设置里提供"律动强度"滑块（0 到 100%）。
• 壁纸态自动乘 0.5；前台全屏应用时只保留低频窗灯脉动。
• 没有音频或静音超过 10 秒，灯光秀在 6 秒内淡出。

隐私模式
• 一键开关，托盘菜单和快捷键都能切换。
• 开启后：步骤标题换成"步骤 4/7"，曲名换成"正在播放"，船身类别隐藏，悬停卡不显示具体文字。
• 默认设置：步骤标题和曲名在本机显示；浏览器只取类别，不取网址和标题，任何模式下都不取。
• 截图检测：系统截图快捷键触发时不做处理（检测不可靠），所以隐私模式要在设置首页醒目位置说明。
产品结构
核心对象只有一个"城市"：壁纸态和互动态是看它的两种方式，回放是把时间游标拨回过去，编辑改的是规则，设置只管系统层面的事。
壁纸态（默认）
• 挂在桌面图标下面（WorkerW 层），不接收鼠标，12 fps，只画变化的格子。
• 只显示需要你行动的提示（等待确认）和 5 秒内消失的文字。
互动态
• 快捷键或托盘唤醒：同一个渲染窗口从 WorkerW 挪出来，变成置顶全屏窗口，30 fps；退出时挪回去，画面连续不重载。
• 鼠标是提灯，悬停出说明卡；点天空放烟花；左下角状态行；右侧控制台（场景、主题、字格密度、律动强度、隐私模式）。
• 底部时间轴即回放入口：拖动到过去，世界按事件流重演；时间轴上用颜色条标出 Agent 会话、音乐段落和离开时段。第一版只做"今日回放"和"今日 30 秒延时摄影"导出。

传输
• 壳内采集（系统、音频、媒体、在场）由 Rust 核心直接通过 Tauri 事件推给前端。
• 外部来源（Claude Code hooks、Codex 监听器、浏览器扩展）向 http://127.0.0.1:<port>/event 发 POST，带启动时生成的随机令牌，只监听回环地址。
记录与回放
• 除 audio.frame 外的事件追加写入按天分割的 JSONL 文件；每 5 分钟写一个世界快照（种子、规则版本、各实体状态），用于快速跳转。
• 回放 = 从最近的快照开始，按 ts 重新喂事件。所有随机数必须来自带种子的生成器，禁止 Math.random() 进入世界逻辑。
• 日志默认保留 14 天，在设置里可改。

降级顺序
1. 前台是全屏应用（游戏、视频、演示）：暂停渲染，只保留采集和日志。
2. 使用电池：壁纸态降到 6 fps，关闭频谱楼和雨粒子。
3. 合成耗时连续 5 秒超预算：云和雾改为每 4 帧更新一次，倒影只采样隔行。
4. 4K 屏：字格密度自动选"粗"，或者内部按 1080p 字格数渲染。
自身反馈环
采集 CPU 时要减去壁纸自身进程（壳、WebView 子进程、采集线程）的占用，否则"画得越多越热、越热画得越多"。
Codex 计划：仓库与约定
用一个仓库装三块东西：TypeScript 前端（世界和渲染）、Tauri 2 的 Rust 壳（壁纸层、托盘、本地服务、系统采集）、几个独立的外部采集器。原型 HTML 放进 reference/ 只读，作为美术和行为的对照标准。

技术选型
• 前端：TypeScript strict、Vite、原生 WebGL2（不引 three.js 或 Pixi）、Vitest。
• 壳：Tauri 2（WebView2）。Rust 侧用 windows crate 调 Win32 和 WinRT（WorkerW、SMTC 媒体会话、WASAPI loopback、PDH 性能计数器）。
• 字体：Sarasa Mono SC 子集化后随应用打包，ASCII 部分仍用程序字形和 JetBrains Mono。
• 外部采集器：Node 或 Rust 小可执行文件均可，要求零依赖安装。
编码约定（写进 AGENTS.md）
• 世界逻辑全部确定性：随机数只能来自 world/rng.ts 的带种子生成器；时间只能来自世界时钟。
• 合成热路径（compose 和 step）不分配对象和数组，颜色用三个标量传，不用 [r,g,b]。
• 每个场景、地标、天气、事件映射都是数据或纯函数，可单独测试。
• 改画面的提交必须附上前后对比截图（开发页的固定种子画面）和每帧耗时。
• UI 文案用简体中文，句子短，不用感叹号，不用"A · B · C"式的点号串。
